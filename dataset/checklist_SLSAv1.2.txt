SLSA v1.2 Build Track — Compliance Checklist
Reference: https://slsa.dev/spec/v1.2/build-track-basics
============================================================

BUILD L1: PROVENANCE EXISTS
Definition: Package has provenance showing how it was built. Can be used to
prevent mistakes but is trivial to bypass or forge.

  Software Producer
  -----------------
  [ ] Follow a consistent build process so that others can form expectations
      about what a "correct" build looks like.
  [ ] Run builds on a Build L1-compliant platform (hosted, shared or dedicated
      infrastructure — e.g. GitHub Actions, Google Cloud Build, Travis CI).
  [ ] Distribute provenance to consumers using ecosystem conventions.

  Build Platform
  --------------
  [ ] Automatically generate provenance describing how the artifact was built,
      including: what entity built the package, what build process was used,
      and what the top-level inputs to the build were.

  Provenance Content
  ------------------
  [ ] Provenance includes buildDefinition.buildType
      (identifies the template used to perform the build).
  [ ] Provenance includes buildDefinition.externalParameters
      (all user-controlled inputs to the build).
  [ ] Provenance includes runDetails.builder.id
      (URI indicating the transitive closure of the trusted build platform).


------------------------------------------------------------
BUILD L2: HOSTED BUILD PLATFORM
Definition: Forging the provenance or evading verification requires an explicit
attack, though this may be easy to perform. Deters unsophisticated adversaries
or those who face legal or financial risk.
(Cumulative — all L1 requirements still apply.)

  Software Producer
  -----------------
  [ ] Run builds on a Build L2-compliant hosted platform.
  [ ] Distribute signed provenance to consumers.

  Build Platform
  --------------
  [ ] Platform generates and signs provenance itself (during the original build,
      an after-the-fact reproducible build, or an equivalent system).
  [ ] Provenance generated by the control plane, not by a tenant.
  [ ] Data in provenance sourced directly from the build platform; platform
      implements security controls preventing tenant tampering.

  Consumer
  --------
  [ ] Validate provenance authenticity via the build platform's digital
      signature before trusting the provenance.

  Provenance Authenticity
  -----------------------
  [ ] Provenance carries a digital signature from the build platform's private
      key.
  [ ] Signing method supports transparency log or timestamping (recommended).


------------------------------------------------------------
BUILD L3: HARDENED BUILDS
Definition: Forging the provenance or evading verification requires exploiting
a vulnerability beyond the capabilities of most adversaries.
(Cumulative — all L1 and L2 requirements still apply.)

  Build Platform
  --------------
  [ ] Prevent cross-run influence — runs cannot influence one another, even
      within the same project.
  [ ] Secret material used to sign provenance is inaccessible to user-defined
      build steps.
  [ ] Every field in the provenance is generated or verified by the build
      platform (user steps cannot inject or alter content).
  [ ] Secret material stored in a secure management system, never in the user
      build environment.

  Isolation Strength
  ------------------
  [ ] Build environment cannot access platform secrets (signing keys, etc.).
  [ ] Concurrent builds cannot influence each other's memory.
  [ ] Ephemeral build environment provisioned for each build; previous builds
      cannot persist environmental changes.
  [ ] Cache poisoning is prevented; output remains identical regardless of
      cache usage.
  [ ] Remote services accessed during the build are captured in
      provenance externalParameters.

  Provenance Completeness
  -----------------------
  [ ] externalParameters fully enumerated (all user-controlled inputs listed
      completely; they are untrusted and must be verified downstream).
  [ ] resolvedDependencies captured on best-effort basis (artifacts needed
      during build execution recorded in provenance).


============================================================
SLSA v1.2 — Key Definitions
------------------------------------------------------------
Producer     : Party creating and providing software to others.
Verifier     : Party inspecting artifact provenance to determine authenticity.
Consumer     : Party using software provided by producers.
Platform     : System allowing tenants to run builds; the transitive closure of
               software and services trusted to faithfully execute the build.
Control plane: Build platform component that orchestrates each independent build
               execution and produces provenance.
Build env    : Independent execution context in which the build runs,
               initialized by the control plane.
Provenance   : Attestation (metadata) describing how outputs were produced,
               including identification of the platform.
============================================================
